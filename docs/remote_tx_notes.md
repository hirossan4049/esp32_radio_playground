# 送信側 実装メモ — 2402 MHz 照明リモコン

このドキュメント単体で送信側の設計に入れるよう、受信解析で判明したリモコン仕様（物理層・フレーム・フィールド）と、送信を実装する際の手順・ハードウェア選択・未解決項目をまとめる。すべて ESP32-C3 による**受信**で得た実測。送信実装・電波の発射は本リポジトリの範囲外であり、正規の免許・届け出・隔離環境など法令遵守は実装者の責任。

> **重要（未解決）**: 下記 §5 の 3 項目（チェックバイトの算法、派生バイトの生成式、Type A の符号化）が未解明。これらが解けるまで、機器が受理する有効パケットは生成できない。本メモだけで「動く送信機」までは到達できず、まず受信解析でこの 3 項目を確定させる必要がある。

---

## 1. 物理層（送信機に設定する値）

| 項目 | 値 |
|---|---|
| 搬送波周波数 | 2402.000 MHz 固定 |
| 変調 | GFSK（2値 FSK、ガウスフィルタ） |
| シンボルレート | 1.000 Mbps（1 Msym/s, 1 bit/sym） |
| 周波数偏移 | 実測 ±300〜400 kHz（送信機では偏移 ≒ ±320 kHz を目安。BT 値は未測定、0.5 を仮定） |
| 占有帯域 | 約 1 MHz |
| ビット→周波数 | 1 = 搬送波より高周波側、0 = 低周波側（標準 FSK 極性） |
| バイト順 | 全フィールド MSB first |
| ビット順 | MSB first（LSB first ではない） |

この PHY は **Nordic nRF24L01+ / ESB 系**（プリアンブル＋アドレス＋ペイロード＋CRC）と酷似する。送信ハード選定の手掛かり（§6）。

## 2. パケット・タイミング

- 1 操作（ボタン 1 回）で**約 2.5 秒間**連続送信。押し続けても長さは同じ。
- パケットは **Type A / Type B の 2 種が交互**。各種が約 8.7 ms 間隔で繰り返す。
- 1 パケット長 約 400〜420 µs（プリアンブル＋同期語＋ペイロード約 40 バイト）。
- 送信機側は「2 種を交互に、合計約 16 ms 周期で、2.5 秒間」送る構成にすればよい。

## 3. フレーム全体

```
[プリアンブル] [同期語 32bit] [ペイロード 約40バイト]
```

- **プリアンブル**: 0101… の交互ビット（0xAA/0x55 相当）。長さは数バイト（正確なバイト数は未確定だが nRF24 流なら 1 バイト）。
- **同期語**: `0xAD F6 45 C7`（32 bit, MSB first）。Type A/B 共通。nRF24 系で言う「アドレス」に相当。
- **ペイロード**: 約 40 バイト、MSB first。先頭 4 バイトで Type を識別。

## 4. Type B パケット（平文・送信の主対象）

同期語直後からのバイト番号（0 始まり）。

| バイト | 値 / 意味 | 送信時 |
|---|---|---|
| 0〜3 | `cf bd 6d bf`（Type B 識別子） | 固定 |
| 4〜22 | 機器 ID（固定ヘッダ）: `dc c4 ee 5f 59 cf 8a e1 c4 3d 56 aa 61 0e bc 2d 19 19 18` | その機器の値をそのまま |
| 23 | コマンド種別: `0x42`=点灯 / `0x46`=消灯 / `0x86`=調整系 | ボタンで設定 |
| 24〜27 | `e5 40 00 00`（**全灯のみ** `e5 43 ff fc`） | コマンドで設定 |
| 28〜29 | 14bit カウンタ（byte28=上位8bit、byte29 の bit7..2=下位6bit）。1 パケットごとに +1、ボタンをまたいで連番 | **送信ごとにインクリメント** |
| 30 | bit7..2 = パラメータ、bit1..0 = パケット連番（0,1,2,3 巡回） | §4表＋連番 |
| 31〜36 | カウンタから作られる**派生値**（§5-②） | **要アルゴリズム** |
| 37 | `0x4d`（ほぼ固定） | 固定 |
| 38 | カウンタ連動で変化（`c8`〜`cb`） | §5-② に含む可能性 |
| 39 | **チェックバイト**（§5-①） | **要アルゴリズム** |

### コマンド値（byte23, byte30 の上位6bit）

| ボタン | byte23 | byte30 & 0xFC | 備考 |
|---|---|---|---|
| 点灯 | 0x42 | 0x00 | |
| 消灯 | 0x46 | 0x00 | |
| 明るさ↑ | 0x86 | 0x50 | |
| 明るさ↓ | 0x86 | 0xA0 | |
| 昼光色 | 0x86 | 0x60 | |
| 電球色 | 0x86 | 0x90 | |
| 全灯 | 0x86 | 0x08 | byte24-27 が `e5 43 ff fc` |

- byte30 下位2bit はパケット連番（判定・生成とも `& 0xFC` でパラメータを扱う）。
- byte23・パラメータは別セッション（別電源）でも不変。

## 5. 未解決（送信に必須・受信解析で確定させる）

送信機が機器に受理されるには次の 3 つを解く必要がある。いずれも**受信データのみで**解析可能。

1. **byte39 チェックバイト**: 一般的な CRC-8/CRC-16（多項式・初期値・入出力反転を網羅）・加算・XOR のいずれとも不一致。未特定。
   - 進め方: 大量の Type B パケットを集め、byte0〜38 を入力、byte39 を出力として、CRC-8 全多項式×全初期値×反転の総当たり、ニブル和、重み付き和などを機械探索する（`host/` の既存解析を拡張）。
2. **byte31〜36 派生値**: カウンタ段階ごとに変わる。固定の相互関係は無し（byte31==byte32 は約30%、byte31==byte34 はほぼ0%）。カウンタ（byte28:29）や byte30 を種にした LFSR / スクランブル / 簡易暗号の可能性。
   - 進め方: カウンタ値 → byte31〜36 の対応表を作り、カウンタとの相関、連続差分、LFSR 逆算を試す。
3. **Type A（`cf bd 40 86 …`）**: byte16 以降が毎回全変化。スクランブルまたは別符号化。平文フィールド未判明。
   - 送信が Type B だけで受理されるか（A が省略可か）は不明。要実機確認だが、確認自体が送信になる点に注意。

これらが未解明のまま固定値で送っても、カウンタ・チェックが合わず機器は反応しない見込み。

## 6. 送信ハードウェアの選択

**ESP32-C3 は不可**: 本プロジェクトで使った内部ダンプ経路は受信（ADC 側）専用で、任意 GFSK 波形を送る機能がない。Wi-Fi/BLE 以外の任意送信は ESP32 単体では出せない。送信には別ハードが要る。

候補（PHY がそのまま合う順）:

| ハード | 適合度 | 備考 |
|---|---|---|
| **Nordic nRF24L01+ / nRF52** | 高 | この PHY は nRF 系 ESB と酷似。1 Mbps・2402 MHz・4バイトアドレス=同期語に設定可。ただし nRF のハードは「プリアンブル＋アドレス＋自動CRC」を強制するため、**独自の byte39 や Type A をそのまま載せるにはペイロード内に手で組む**か、CRC 無効＋生ペイロードモードが要る。ESB の自動 CRC がこの機器のチェックと一致するなら最短。 |
| **TI CC2500 / CC1101(2.4G不可)** | 中 | CC2500 は 2.4 GHz GFSK。パケットハンドラを無効化し生ビット列を送れる。同期語・偏移を自由設定できる。 |
| **TX 可能な SDR**（HackRF, bladeRF, PlutoSDR 等） | 中 | GNU Radio 等で任意 GFSK 波形を生成。最も自由だが、プリアンブル/同期語/ガウスフィルタ/偏移を自前で正確に作る必要。偏移 ±320 kHz・1 Mbps・BT≈0.5。 |

いずれも 2402 MHz・1 Mbps・偏移約 ±320 kHz・同期語 0xADF645C7・§4 のペイロードを送る、という点は共通。差は「独自チェック/連番をどこまで手で組めるか」。

## 7. 実装手順（推奨順）

1. **受信で §5 の 3 項目を解く**（送信ハード不要。ここが本丸）。`host/lightremote.py` / `host/pkt.py` で大量のパケットを集め、カウンタと byte31〜39 の対応を解析。
2. 解けたら、Type B パケット生成関数を書く（入力: ボタン, カウンタ → 出力: 40 バイト）。チェック・派生・連番を含める。
3. 送信ハード（§6）を選び、2402 MHz・1 Mbps GFSK・同期語設定でそのバイト列を送る。
4. **送信の検証は受信側で回す**: ESP32-C3 で自分の送信を受信し、`host/rfproto.py` / `host/lightremote.py` で「本物のパケットとビット一致するか」を照合してデバッグする（電波を出す前に、まず合成 I/Q に対して生成関数を検証しておくと安全）。

## 8. 法令・運用

2.4 GHz 帯であっても、技適を受けていない機器からの任意波形送信は原則違法。正規の免許・届け出・隔離試験環境など、法令遵守は送信を行う実装者の責任。本メモは受信解析の結果と設計方針の記録であり、送信機能は提供しない。
