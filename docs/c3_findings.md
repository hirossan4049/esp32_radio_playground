# ESP32-C3 受信経路の調査メモ

更新日: 2026-10-17
対象ボード: ESP32-C3 (QFN32, revision v0.4, 内蔵 4MB フラッシュ, 40 MHz 水晶), Espressif 純正 USB Serial/JTAG (303a:1001),
USB シリアル番号 = MAC E8:F6:0A:16:BD:84。開発ボード型式は不明（基板上の PCB アンテナ使用）。
ツール: ESP-IDF v5.2.1 (`~/Documents/fun/pg/fun/esp-idf`), riscv32-esp-elf gcc 13.2.0, esptool 5.4.0, macOS。
ファームウェア: `firmware/`（本リポジトリ）。ホスト: `host/rxprobe.py`。

## 区分の凡例
- [実測] このボードで測定・確認した事実
- [静的] ライブラリ逆アセンブル等から読み取った事実（ハード未検証）
- [文献] 他者 README / 文書の主張
- [仮説] 未検証

## 計画との差分
- 計画書の第一候補は ESP32-S3 だが、接続されている実機は **ESP32-C3**。既知の I/Q 受信実績（eSpDR / esp32-sdr-trx）は S3 のみ [文献]。
  C3 で同等の経路が使えるかは本調査で確認する（S3 の結果を横滑りさせない）。

## 既知事例の要点（Phase 0 読解）
- esp32-sdr-trx / eSpDR (S3) [文献]:
  - 受信 LO の法則: `LO = 960 MHz + 30 MHz × W/65536`（W: 24bit SDM 語、40 MHz 水晶）。PLL が実際にロックするのは約 2210–2790 MHz。
  - 5/6 変換モード（アナログ CKGEN ブロック 0x65 reg0 bit4）で実効 LO = PLL×5/6 → 1.84–2.33 GHz。**これ以外の分周比は未発見**。
    470–710 MHz には PLL 座標の約 1/4〜1/3 が必要で、既知の仕組みでは届かない。
  - ダンプエンジン: 0x60033D5C（制御: bit31 run, bit17 circular, bit16 16Msps, bits0..15 リング長）, 0x60033D60（書込インデックス）,
    0x60033D90（バイトセレクタ, 0x000C2040 で 32bit 語全体）, 0x600C101C（バンク選択）。語形式 I=bits0..9, Q=bits10..19（10bit 2 の補数）。
  - 16 Msps ダンプ → CIC/16 → FIR で 250/333 ksps。USB Full-Speed (0.87 MB/s) が転送上限。16 Msps のフル取得は FPGA 必須。
- ESP32-DATV (C3) [文献]: libphy の `set_chanfreq`/`phy_set_freq` で 2200–2800 MHz に同調（S3 と同じ 30 MHz×(32+W/65536) 法則）。
  `dactrig` 用 DAC 再生エンジン 0x60033D64、SRAM バンク 0x3FCB0000、所有権レジスタ 0x600C1020。送信のみ。

## C3 librftest / libphy の静的解析 [静的]
- `adctrig` は C3 の librftest にも存在し、S3 と同じ 0x60033D5C / 0x60033D60 を使う。SRAM 所有権は 0x600C1020（`(v & ~7) | 2` のあと `| 8`）。
- `adctrig(a0..a7, stack)` の制御語: `((a4<<17)&0x20000) | (a1<<28) | ((!(a3&1))<<16) | (a2<<20) | (a0+1)`。
  run (bit31) をセット後、**bit19 をセット→クリア（パルス）** して書込みを開始。bit18 が完了フラグ。
- rftest の `get_rx_buffer1` は `adctrig(0x2000, 0, 0, 1, 0, 0, 0, 0, 0)` を呼ぶ（モード 0）。
- `phy_chan_dump_cfg` は 0x6001CD0C を触る（S3 と同一アドレス）。
- librftest の `mac_init` は 0x60033D90（ダンプのバイトセレクタ）に **0x000C2040** を書く（S3 の `DUMP_CONFIG_IQ` と同値）。
  通常の Wi-Fi ドライバ初期化ではこのレジスタは 0 のまま（実測）。
- AGC 強制: 0x6001C02C bits24..30 = ゲイン選択, bit23 = force（S3 と同一）。

## 実測 [実測]
### RX-C3-001: ダンプエンジンの起動（2026-10-17）
- 条件: LO 2437 MHz（set_chanfreq(2437)）, PCB アンテナ, RX 強制 (`force_rx_gain(0,40,0)`), Wi-Fi ドライバ起動（mode NULL, promiscuous）。
- 自前シーケンス（bit19 パルス無し）: run ビットは立つが 1 語も書かれず、インデックス 0 のまま。0x60033084 bit30/29 を立てても変化無し。
- `adctrig(8192,0,0,1,0,0,0,0,0)`（ライブラリ呼出）: 8193 語が 0x3FCB0000 に書かれた。
  - 語は `0x2d2d2d2d` のように **同一バイトの 4 回繰返し**（170 種）。S3 で「バイトセレクタ未設定」のときに観測された症状と一致 → C3 でも
    セレクタ相当の設定が必要（アドレス未特定）。現状は 8bit 分の情報しか得られていない。
  - 書込完了まで 238,997 CPU サイクル（160 MHz, phy_printf を含む）→ 下限 5.5 MS/s。正確な値は bit19 パルス版で測定する。
- 解釈: unverified（RF 入力 ON/OFF・周波数変更・LO 変更の対照実験は未実施）。

### RX-C3-002: 自前シーケンスでの取得とサンプルレート（2026-10-17）
- run (bit31) の後に bit19 をパルスすると自前シーケンスでも書込みが始まる [実測]。
- 充填時間（16384 語）: ctrl=0x3FFF → 32,831 サイクル @160 MHz = **79.85 MS/s**; ctrl=0x13FFF（bit16）→ 163,893 サイクル = **15.995 MS/s**。
  S3 の 80/16 Msps と同一 [実測]。bits0..13 = 書込語数−1（0x3FFF で 16384 語 = 64 KiB バンク全体）。
- bit17 を立てた（S3 の circular 相当）場合は即完了し 10 語しか書かれなかった（意味未解明）。
- 0x60033D90 = 0x000C2040 を書いた後の語: 例 `0x24906FE1`。bits20..31 はほぼ固定（0x249）、bits0..9 と bits10..19 が変動。
  S3 の形式（I = bits0..9, Q = bits10..19, 2 の補数）で復号すると I/Q とも平均≈0、σ≈47〜57、|値|≤273（10bit レンジ内）→ S3 と同じ語形式と整合 [実測]。
- 16 MS/s 取得（LO 2437 MHz）の PSD に −3.0 MHz のピーク。LO−RF 規約なら RF 2440 MHz = 40 MHz 水晶の 61 倍高調波（S3 でも報告あり [文献]）。
  LO 掃引でこのピークが LO と共に動くかで、同調が実際に働いているかを判定する（RX-C3-003）。

### RX-C3-003: LO 掃引による同調の実在確認（2026-10-17）
- 条件: 16 MS/s（ctrl 0x13FFF）, 16384 語, PCB アンテナ, ゲイン 40（force_rx_gain）, Welch PSD（1024 点）。外部信号源なし。
- LO 2435 → −5.03 MHz、LO 2437 → −3.00 MHz、LO 2440 → 0 MHz（DC）にピーク: いずれも **RF 2440 MHz** を LO−RF 規約で見た位置 [実測]。
- LO 2440 → −8.00 MHz、LO 2445 → −3.00 MHz、LO 2450 → +2.00 MHz にピーク: いずれも **RF 2448 MHz** [実測]。
  libphy に `phy_2448m_spur_pwr` という関数があり [静的]、既知のチップ内スプリアスと考えられる。
- RF−LO 規約では一貫した RF に対応しないため、符号規約は S3 と同じ **I+jQ = LO − RF** [実測]。
- 解釈: `set_chanfreq`/`phy_set_freq` による設定で受信ミキサの LO が実際に動いている（内部スプリアスが LO 設定に従って移動）。
  ただしマーカーはチップ内部の信号であり、**アンテナ端からの外部 RF の受信そのものは未検証**（RX-C3-005 で実施予定）。
- LO 2435 / 2460 で +7.0〜7.9 MHz に幅約 1 MHz のピーク群（RF 換算 2427.3 / 2452.5 MHz 付近）。再現性・正体は未確認（BLE か、帯域端の折返しの可能性）。

### RX-C3-004: PLL ロック範囲の地図化（水晶高調波マーカー法, 2026-10-17）
- 方法: LO = 40k + 3 MHz に設定し、16 MS/s の PSD で +3.000 MHz（RF = 40k MHz の 40 MHz 水晶高調波、LO−RF 規約）のレベルを PSD 中央値に対して測る。
  マーカーが出れば LO は実際にその付近にある。外部機器不要。1963〜3083 MHz を 40 MHz 刻み。
- 結果 [実測]: マーカーは **LO 2203〜2803 MHz** で検出（5〜20 dB; 2283 は 1.3 dB で判定不能）。1963〜2163 と 2843〜3083 では検出なし。
  → C3 の通常モードの PLL ロック範囲は約 **2.2〜2.8 GHz**（S3 の 2210〜2790 と同等）。端点はこの個体の値。
- アナログブロック 0x62（RFPLL）reg12: ロック時（2437）= 0x00、非ロック時（2003）= 0x04、（3003）= 0x0A → **bits[3:2] がロック検出**（S3 と同じ判定式）[実測]。
- ブロック 0x63（SDM）reg3..5 = W: 2437 MHz で 0x313BBB、2003 MHz で 0x22C444 → `30 MHz × (32 + W/65536)` の法則と一致 [実測]。
- ブロック 0x65（CKGEN）reg0 = 0x63（S3 の報告値と同じ）、reg1 = 0x88、reg2 = 0x10。ブロック 0x67（BB フィルタ）reg4..7 = 23 23 0c 0c。
- 強い外来信号で |I| が 512 で飽和した LO（2443, 2483, 2563, 2603, 2643）がある。ゲイン 40 固定のため。

### RX-C3-005: 5/6 変換モードの C3 での検証（2026-10-17）
- 予測: PLL 座標 2403 MHz、通常モードでは 2400 MHz 高調波が +3.0 MHz。CKGEN 0x65:0 bit4 を立てて実効 LO が 5/6 倍になれば
  実効 LO = 2002.5 MHz → 2000 MHz 高調波（50 倍）が **+2.5 MHz** に現れ、+3.0 MHz は消えるはず。
- 結果 [実測]: 0x63 → 0x73 で +3.0 MHz: 10.2 dB → −1.6/+0.4 dB（消失）、+2.5 MHz: −2.8 dB → **+15.2/+16.1 dB**（出現、2 回再現）。
  0x63 に戻すと +3.0 MHz が 15.3 dB で復帰、+2.5 MHz は 0.9 dB。
- 解釈: **ESP32-C3 にも 5/6 変換モードが存在し、S3 と同じレジスタ・同じビットで切り替わる**。実効 LO の下限は約 2203×5/6 ≈ 1836 MHz と見込まれる
  （下限の実測は未実施）。5/6 モードでは DC 近傍（±0.3 MHz）に強い成分が出る（DC オフセット/LO リーク増大の可能性、未解明）。
- 地デジ帯（470〜710 MHz）には比 0.17〜0.32 が必要で、5/6 では届かない。他の分周比の有無は RX-C3-006 で探索。

### RX-C3-006: CKGEN（アナログブロック 0x65）reg0..2 の単ビット反転探索（2026-10-17）
- 方法: 各ビットを反転 → PLL 座標 2403/2443/2523/2683 MHz で 16 MS/s 取得 → +3.0 MHz マーカー（RF 40k）の有無、最強ピーク、I の σ、
  ダンプ充填時間（サンプルクロック）を記録 → 元に戻して復帰確認。生データ: `logs/RX-C3-006_ckgen_explore.json`。
- 結果 [実測]:
  - ダンプのサンプルクロックはどのビットでも 15.995 MS/s のまま（CKGEN はダンプクロックに影響しない）。
  - マーカーが **全 PLL 座標で消失** したビット: reg0 bit2（0x67）, reg0 bit5（0x43）, reg0 bit6（0x23）。bit2/bit5 では PLL 2523/2683 で −0.63〜−0.70 MHz に
    PLL に依存しない強い成分（ベースバンド側の人工物）、2403/2443 では I σ が 13〜16 と低い（受信経路の停止に近い）。bit6 では広帯域に σ 70〜120。
  - 他のビット（reg0 bit0,1,3,7、reg1 全ビット、reg2 全ビット）はマーカー維持 → LO 変換比には無関係（reg2 bit2 は 2403 のみで +0.95 MHz に 24 dB の人工物）。
  - すべて復帰可能、最終確認でマーカーは正常。
- 解釈: 「マーカー消失」だけでは「別の変換比」と「受信停止」を区別できない。PLL 座標を細かく掃引して別比の 40 MHz コムが現れるかで判別する（RX-C3-007）。

### RX-C3-007: 候補ビットの変換比フィット（PLL 5 MHz 刻み掃引, 2026-10-17）
- 方法: CKGEN reg0 を候補値にして PLL 座標 2203〜2803 MHz を 5 MHz 刻みで掃引（各 121 点、16 MS/s）。観測した狭帯域ピーク（中央値 +7 dB 以上、|f|>0.4 MHz）が
  「実効 LO = r × PLL に対する 40 MHz 高調波コム（offset = LO_eff − 40k）」として説明できる割合を、分母 12 以下の分数 r について集計。
  生データ: `logs/RX-C3-007_ratio_ck*.json`。
- 正の対照 0x73（既知の 5/6）: r = 5/6 が 11/46（24%）で最良、次点 9/11 は 7%。方法が比を検出できることを確認 [実測]。
  （予測線の 24% しか観測されないのは高調波ごとの強度差と閾値のため。）
- 0x67（bit2）, 0x43（bit5）: 突出する r なし（最良 7%、しかもヒットは PLL に依存しない ±0.55〜0.70 MHz の固定人工物との偶然の一致）。
  I σ ≈ 140 で ±0.5 MHz 付近に対称な強い線 → 受信機内部のトーン/発振に近く、コムは見えない [実測]。
- 0x23（bit6）: ピークなし（ノイズ状）[実測]。
- 結論: **この個体の CKGEN reg0..2 の単ビット反転では、5/6 以外の受信変換比は見つからなかった**。bit2/5/6 は受信経路を壊す（または別経路に切り替える）が、
  40 MHz コムで観測可能な別比の LO は生じない。複数ビット同時変更、他のアナログブロック、デジタル側レジスタは未探索。
- 研究上の含意: 地デジ帯（470〜710 MHz、比 0.17〜0.32）に LO を持ち込む既知・新規の手段は現時点で見つかっていない。
  C3 の到達範囲は S3 と同じ約 1.84〜2.8 GHz（5/6 の下限は未実測）。

### RX-C3-008: 周辺電波によるバースト統計（外部 RF 受信の示唆, 2026-10-17）
- 方法: 1 ms（16384 語 @16 MS/s）のキャプチャを各 LO で 40 回。エンベロープ（64 サンプル平均）の最大/中央値 > 3 を「バースト」、|I| ≥ 500 を飽和とみなす。
  Mac の Wi-Fi スキャンでは 2.4 GHz 帯の最強 AP はチャネル 6（2437 MHz, −57 dBm）。生データ: `logs/RX-C3-008_ambient.json`。
- 結果 [実測]: LO 2437 MHz: バースト 9/40 と 6/40（2 回）、飽和 8 と 6。LO 2300 MHz: バースト 1/40、飽和 0。LO 2600 MHz: バースト 11/40、飽和 9。
- 解釈: 2300 MHz（日本では強い下り送信のない帯域）でほぼ静かで、2437 MHz（Wi-Fi）と 2600 MHz（2.5 GHz 帯 TD-LTE/AXGP の可能性）でバーストが出るのは
  外部 RF を受けていることと整合する。ただし入力 ON/OFF 対照がないため **示唆にとどまる（unverified）**。制御可能な 2.4 GHz 送信源（スマホのテザリング ON/OFF 等）で
  4 点確認（入力 ON/OFF・RF 周波数変更・LO 変更・対照）を行うのが次の課題。ゲイン固定 40 で飽和が多いので、外部信号試験ではゲインを下げる。

## 現時点の結論（C3, 2026-10-17）
1. ESP32-C3 の Wi-Fi 受信経路から **80 / 16 MS/s の 10bit I/Q を内部 SRAM に取得できる**（S3 と同じエンジン・同じ語形式・同じバイトセレクタ値）。レベル A/B の足場。
2. LO は `30 MHz × (32 + W/65536)` で設定でき、通常モードのロック範囲は約 2.2〜2.8 GHz。**5/6 変換モードも C3 で動作**し、約 1.84 GHz まで下げられる見込み。
3. CKGEN の単ビット探索では 5/6 以外の変換比は見つからず、**470〜710 MHz に LO を置く手段は未発見**。地デジ帯の応答（H2/H3）は信号発生器なしでは検証不能。
4. 帯域: 1 ms 単発取得は可能だが、連続ストリーミングは USB Serial/JTAG の帯域（S3 で 0.87 MB/s 報告）が壁。フルセグ（6 MS/s 複素）は転送不能、
   ワンセグ相当（約 0.5 MS/s × 2 byte = 1 MB/s）も 8bit 化や内部処理なしでは不足。SRAM 単発（最大 16384 複素サンプル ≈ 1 ms @16 MS/s）では OFDM 同期の検証には短い
   （ISDB-T モード 3 の有効シンボル長は 1.008 ms）。128 KiB バンク全体や PSRAM なしの C3 では長時間取得に別の工夫が要る（Phase 4 の課題）。
