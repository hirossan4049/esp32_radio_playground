# 2402 MHz 照明リモコンの解析結果（RX-C3-025〜028, 2026-10-18）

対象: ユーザ宅の LED 照明用リモコン（型番未確認）。ESP32-C3 の I/Q 取得（4 / 16 MS/s, イベントモード）と `host/remote_live.py`（自動ゲイン・多数決復調）で解析。受信のみ。

## 物理層 [実測]
- 2402 MHz 固定、1 Mbps GFSK（周波数弁別器のクロック線で確認、2 Mbps ではない）、占有幅約 1 MHz。
- 1 回の操作で約 2.5 秒間、**16 ms 周期**でパケットを送る。パケット長約 420 µs（約 400 bit）。約 80 µs の短いパケットも混じる。
- I+jQ = LO − RF の規約のため、復調では共役を取る（FSK 極性反転）。
- 受信強度: ESP32 から 20〜30 cm でゲイン 30 前後が適正。ゲイン 38 で 20 cm は飽和。

## パケット構造 [実測]
`プリアンブル(0101…)` → `同期語 0xADF645C7` → 以下 40 バイト（MSB first）。2 種類のパケットが 16 ms ごとに交互に出る。

### 種類 B（`cf bd 6d bf …`）— 平文で読める
| バイト | 内容 |
|---|---|
| 0〜21 | 固定（機器 ID と思われる: `cf bd 6d bf dc c4 ee 5f 59 cf 8a e1 c4 3d 56 aa 61 0e bc 2d 19 19`） |
| 22 | `0x18` |
| 23 | **コマンド種別**: `0x42` 点灯、`0x46` 消灯、`0x86` 調整系 |
| 24〜27 | `e5 40 00 00`（全灯のみ `e5 43 ff fc`） |
| 28〜29 | **14 bit カウンタ**（28 = 上位、29 の bit7..2 = 下位 6 bit）。送信中に約 1.5 秒ごとに +1、ボタンを変えても連番 |
| 30 | bit7..2 = **パラメータ**: `0x50` 明るさ↑、`0xa0` 明るさ↓、`0x60` 昼光色、`0x90` 電球色、`0x08` 全灯（全灯形式のとき）。点灯/消灯では `0x00`。bit1..0 = パケット連番（0,1,2,3 を繰り返す） |
| 31〜36 | カウンタ段階ごとに変わる派生値。31≈32≈34 の関係あり。生成式は未特定 |
| 37〜38 | `4d c8`〜`4d cb` |
| 39 | チェック値。一般的な CRC-8/16・加算・XOR のいずれとも一致せず、未特定 |

### 種類 A（`cf bd 40 86 …`）
バイト 16 までは固定（16 は `88〜8b` の 2 bit フィールド）、17 以降はカウンタ段階ごとに全バイトが変わる。スクランブル（または別の符号化）と推定 [仮説]。

## 検証の経緯
- 同じボタンを押しても `30` の下 2 bit が 1,2,3,0 と巡るため（明るさ↑ ×5 で `51 52 53 50`）、当初「状態値」に見えた変動は連番だった。
- 時刻順に 1 回ずつ押した試験（点灯→消灯→明るさ↑→明るさ↓→全灯→昼光色→電球色）で 7 回とも検出し、上表の対応を確定（`logs/remote_live.txt` 15:30:58〜15:32:08）。
- 初期の録音でボタン名とパラメータが食い違ったのは、押した順番の混在と取りこぼしによる。

## ツール
- `host/remote_live.py`: 常時受信し、押した瞬間に `PRESS 種別 パラメータ名 …` を表示（自動ゲイン・閾値、1 秒窓の多数決）。
- `host/lightremote.py`: 録音（SigMF）から同じ表を出す。`--vote` で弱信号向け多数決。
- `host/pkt.py`: 未知信号向け。`--find` で同期語探索、`--sync` でパケット一覧と差分。
- 送信（リプレイ）は本研究の受信専用方針により実装しない。

## 同系列の別リモコンを調べる（汎用ツール host/rfproto.py）
機器固有の決め打ちを持たない解析エンジン。受信のみ。
```
# 1. 録音（別リモコンでも 2402 MHz 付近・1 Mbps GFSK なら同じ手順。周波数は掃引で確認）
python3 host/capture.py --freq 2402 --rate 16000000 --gain 25 --thr 20 --duration 120 --output captures/web/other

# 2. 同期語を自動探索（プリアンブル後に最頻出する 32bit 語）
python3 host/rfproto.py scan captures/web/other.sigmf-meta

# 3. フィールド自動推定＋プロファイル保存（パケット種別ごとに FIXED/COMMAND/COUNTER/CHECK を色分け）
python3 host/rfproto.py learn captures/web/other.sigmf-meta --name other_remote --gap 4
#   -> profiles/other_remote.json（同期語・レート・機器ID・コマンド/カウンタ/チェックの位置）

# 4. 以後、録音がどの機器かを自動判定＋デコード
python3 host/rfproto.py id captures/web/any.sigmf-meta

# 5. ライブ表示をそのプロファイルで（押した瞬間にコマンドバイトを表示）
python3 host/remote_live.py --profile other_remote --freq 2402 --rate 16000000
```
`profiles/living_light.json` が今回の照明リモコンの実例。`labels` に「コマンドバイト列→ボタン名」を書くと、ライブ表示が
`PRESS 明るさ↑ command 86 50 …` のように名前付きで出る。別機種では learn 後に同じ要領でボタン名を書き足す。
送信（リプレイ）は本研究の受信専用方針により提供しない。
