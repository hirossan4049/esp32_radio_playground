# 照明リモコン 無線仕様（2402 MHz）— 実測まとめ

対象: ユーザ宅の LED 照明用 2.4 GHz リモコン（メーカー・型番未確認）。ESP32-C3 の I/Q 取得で受信・復調して得た仕様のみを記す。全て受信による実測で、データシート等の出典はない。送信（リプレイ）は行っていない。

---

## 1. 物理層（PHY）

| 項目 | 値 | 備考 |
|---|---|---|
| 中心周波数 | **2402 MHz** | 固定。周波数ホッピングなし（他チャネルでは未検出） |
| 変調 | **GFSK**（2値 FSK） | 周波数弁別器のクロック線で確認 |
| シンボルレート | **1 Mbps**（1 Msym/s） | 0.25/0.5/2 Mbps を試して 1 Mbps のみ一致 |
| 占有帯域幅 | 約 **1 MHz**（−10 dB 幅） | |
| FSK 偏移 | 約 ±300〜400 kHz（85 パーセンタイル） | 1 Mbps GFSK として妥当 |
| ビット極性 | 周波数が高い側 = 1 | I+jQ = LO−RF のため復調時に共役を取る（極性反転） |
| 送信周波数誤差 | +35〜+80 kHz（ESP32 の水晶基準） | 機器と ESP32 の水晶差。パケット内は一定 |

## 2. バースト／タイミング

| 項目 | 値 |
|---|---|
| 1 パケットの長さ | 約 **400〜420 µs**（約 400 ビット前後、ペイロード 40 バイト級） |
| ボタン 1 回で送る時間 | 約 **2.5 秒間**連続送信（押し続けても同じ長さ） |
| パケット反復 | 同一種のパケットが約 **8.7 ms** 間隔で繰り返す（下記 2 種が混在） |
| 短パケット | 約 80 µs の短いバーストも多数混じる（用途未特定） |

## 3. フレーム構造（共通）

```
[プリアンブル 0101…] → [同期語 0xADF645C7（32 bit, MSB first）] → [ペイロード 約 40 バイト]
```

- 同期語 **0xADF645C7** は 2 種類のパケットで共通。出現頻度が他候補より 1 桁以上高く、確実に同期語。
- ペイロードは MSB first。**2 種類のパケットが交互に送られる**（下記 Type A / Type B）。どちらも同じ同期語の後に続く。

---

## 4. パケット Type B（`cf bd 6d bf …`）— 平文で読める

同期語の直後からのバイト番号（0 始まり）。

| バイト | 値 / 意味 |
|---|---|
| 0〜3 | `cf bd 6d bf`（Type B 識別） |
| 4〜22 | **固定ヘッダ**（機器 ID と推定）: `dc c4 ee 5f 59 cf 8a e1 c4 3d 56 aa 61 0e bc 2d 19 19 18` |
| 23 | **コマンド種別**: `0x42` 点灯 / `0x46` 消灯 / `0x86` 調整系 |
| 24〜27 | `e5 40 00 00`（**全灯のみ** `e5 43 ff fc`） |
| 28〜29 | **14 ビットカウンタ**: バイト28 = 上位 8 bit、バイト29 の bit7..2 = 下位 6 bit。1 パケットごとに **+1**。送信中ずっと増加し、ボタンを変えても連番で続く |
| 30 | bit7..2 = **パラメータ**（調整系のとき）、bit1..0 = **パケット連番**（0,1,2,3 を巡回） |
| 31〜36 | カウンタ段階ごとに変わる**派生値**。生成式は未特定（単純な固定関係は無し: byte31==byte32 は 30% 程度、byte31==byte34 はほぼ 0%） |
| 37 | `4d`（ほぼ固定） |
| 38 | `c8`〜`cb`（カウンタに連動して変化） |
| 39 | **チェック値**。一般的な CRC-8 / CRC-16（多項式・初期値・反転を網羅）・加算・XOR のいずれとも不一致。算法未特定 |

### コマンド対応表（バイト23、バイト30 の上位 6 ビット）

| ボタン | byte23 | byte30 & 0xFC | 補足 |
|---|---|---|---|
| 点灯 | `0x42` | `0x00` | |
| 消灯 | `0x46` | `0x00` | |
| 明るさ↑ | `0x86` | `0x50` | |
| 明るさ↓ | `0x86` | `0xA0` | |
| 昼光色 | `0x86` | `0x60` | |
| 電球色 | `0x86` | `0x90` | |
| 全灯 | `0x86` | `0x08` | バイト24〜27 が `e5 43 ff fc` の別形式 |

- 同じボタンを連続で押すと byte30 の下位 2 ビットが `01→02→03→00` と巡る（例: 明るさ↑ ×5 で `51 52 53 50`）。これは**パケット連番でありボタン情報ではない**。パラメータ判定は必ず `& 0xFC` でマスクする。
- byte23・byte30 上位 6 ビットは**セッションをまたいでも同じ値**（別日・別電源でも不変）。

## 5. パケット Type A（`cf bd 40 86 …`）

| バイト | 値 / 意味 |
|---|---|
| 0〜3 | `cf bd 40 86`（Type A 識別） |
| 4〜15 | 固定: `d2 e4 7c 17 b8 33 23 28 07 84 3f 3d`（バイト16 は `88〜8b` の 2 ビットフィールド） |
| 16〜39 | カウンタ段階ごとに**全バイトが変化**。スクランブルまたは別符号化と推定。平文フィールドは読めていない |

Type A はボタンを変えても毎回ほぼ全バイトが変わるため、現状はボタン判別に使えない。ボタン情報は Type B から読む。

---

## 6. 未解明の点

- **バイト31〜36 の派生値の生成式**（カウンタからどう作られるか）。
- **バイト39 のチェック値の算法**（標準 CRC では不一致）。
- **Type A の符号化**（スクランブル多項式／鍵）。
- メーカー・型番。既知プロトコル（Telink 系、XN297 系など）との同定は未実施。

これらは主に送信再現に必要な要素であり、本調査は受信専用方針のため追っていない。Type B の平文フィールドだけで「どのボタンが押されたか」は完全に判別できる。
